- Python style is governed by `.editorconfig`, `pyproject.toml`, and custom instruction files under `.github/HH-*.md`.
- Formatting: Python uses tabs, LF line endings, final newline, trimmed trailing whitespace, max line length 140. Markdown/TOML/YAML use 2 spaces and max line length 102.
- Strings: preserve repository style; default to single quotes in code, triple double quotes for docstrings.
- Naming: camelCase for variables, parameters, functions, and methods except pytest `test_*` and Python dunders. Use full words, no abbreviations, no single-character identifiers, and keep one identifier = one meaning.
- Function names should be explicit and role-bearing; user instructions prefer subject-verb-object naming and domain-canonical terminology.
- Typing: annotate comprehensively, prefer PEP 585/604 syntax, avoid `Any` / bare containers, prefer `Sequence` / `Mapping` for read-only inputs, and use `Protocol`, `TypedDict`, `TypeVar`, and overloads when they sharpen contracts.
- Architecture: semiotics-first, domain-driven, mostly functional / transformational style. Keep single source of truth, avoid redundant aliases, and preserve semantic helper abstractions.
- Post-defensive rule: once data is validated, trust invariants, fail fast, and do not add defensive branches or silent recovery in hot/internal paths.
- Docstrings: only add or edit when asked or when the task requires them. Use the custom NumPy-style rules from `.github/HH-docstrings.md`.
- Testing rules for new/edited tests: fixtures live in `tests/conftest.py`; every test uses `@pytest.mark.parametrize`; assertions need informative messages; prefer deterministic data from `tests/dataSamples/`.
- Tooling preference: prefer MCP / Serena tools for navigation, docs, diagnostics, refactors, and test execution. Use the terminal only as a fallback when an MCP path is unavailable.
